# Правило: НЕТ новым markdown-файлам без разрешения

## ⛔ Запрет

**НИКОГДА** не создавай новые файлы с расширением `.md` без **ЯВНОГО** разрешения пользователя.

## Что считается markdown-файлом

- `.md`
- `.markdown`
- Файлы README, CHANGELOG, CONTRIBUTING и т.п.
- Документация в формате markdown
- Любые заметки, гайды, инструкции в `.md`

## Когда НЕЛЬЗЯ создавать

❌ **Никогда не создавай автоматически:**
- После завершения задачи
- «Для документирования изменений»
- «Для удобства разработки»
- README, CHANGELOG, ROADMAP
- Архитектурные заметки
- Инструкции по развёртыванию
- Планы, туду-листы, чеклисты

## Когда МОЖНО создавать

✅ **Только при явной команде пользователя:**
- «создай файл README.md»
- «добавь документацию в CHANGELOG.md»
- «сделай гайд по …»
- «запиши это в .md файл»

## Куда писать документацию

Если изменения требуют обновления документации **проекта** — используй **существующие** файлы:

| Что документируешь | Куда писать |
|---|---|
| Архитектура, структура, контекст проекта | `KODA.md` |
| API, запуск, установка, общее описание | `README.md` |

**Не создавай** `docs/...md`, `ARCHITECTURE.md`, `CHANGELOG.md`, `ROADMAP.md` и т.п. без разрешения.

## Что делать вместо создания файла

1. **Обнови существующую документацию** — добавь в `README.md` или `KODA.md`
2. **Если не уверен, куда** — спроси пользователя
3. **Если нужен новый .md файл** — явно спроси разрешения:
   ```
   Хочешь, создам файл ...md? Или добавлю в README.md / KODA.md?
   ```

## Исключения

Разрешено редактировать без спроса:
- `README.md`
- `KODA.md`

**Запрещено создавать** любые другие `.md` без явного разрешения.

## Нарушение правила

Если ты собрался создать `.md` файл:
- ОСТАНОВИСЬ
- Спроси: «Хочешь, создам markdown-файл для этого?»
- Жди ответа

---

**Приоритет: КРИТИЧЕСКИЙ** 🚨

Это правило имеет наивысший приоритет и не должно игнорироваться.
